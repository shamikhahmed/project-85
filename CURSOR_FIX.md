## Bugs (confirmed in code review)

1. **Sleep shows one stage, not the whole night.** `src/health/projectHealthIntoApp.ts` (asleep block)
   takes the single longest `sleep_asleep` sample. HealthKit and Health Connect return sleep as many
   stage segments (core/deep/REM/light). `healthKitBridge.ts:245` maps every non-`inBed` state,
   **including `awake`**, to `sleep_asleep`.
   Fix: in the bridge, map `awake` to its own id (or drop it) and keep the stages. In the projection,
   group asleep segments into one night per wake date. Segments belong to the same night if the gap
   is ≤ 90 min. Bedtime = first segment start, wake = last segment end, total = sum of asleep minutes
   (exclude awake). Pick the longest night per wake day. Test: 6 fragmented stages plus 2 awake segments
   → one night with the correct bed/wake and total.

2. **Days use the UTC date, not the local date.** `localDay(iso) = iso.slice(0, 10)`, and the wake day
   uses `best.endAt.slice(0, 10)`. If the samples are ISO `Z` strings, early-morning steps, weigh-ins
   and wake times land on the wrong day for any non-UTC timezone.
   Fix: use the local calendar date (date-fns `format(parseISO(iso), 'yyyy-MM-dd')`), the same way the
   existing overnight-wake fix does. Also check `pickDayTotal` and `dedupe.ts` for the same slice.
   Test with `TZ=Asia/Karachi` and `TZ=America/Toronto` (set `process.env.TZ` in the test or a vitest config).

3. **Water is never updated after the first sync.** It is seeded only when the day has no rows. Auto-sync
   runs every 15 min, so the first partial morning value is kept for the whole day.
   Fix: store the synced water as a single source-tagged row per day and replace it on each sync.
   Never touch manual rows. If the day has any manual water row, skip the synced value (manual wins).

4. **Unhandled promise rejection.** In `src/components/CapAutoHealthSync.tsx`, `void run()` has no catch.
   If the plugin throws (permission revoked, HealthKit unavailable), this is an unhandled rejection.
   Fix: wrap it in try/catch, record the error in the existing connection-status state (never reset it to ok),
   and don't set `lastAutoSyncAt` on a throw (current behaviour; keep it and add a test).

5. **Auto-sync before permission.** Confirm that `runFullHealthSync` makes no read calls when Apple / Health
   Connect permission has never been granted. It should return `permission_needed` without errors.
   Add a test.

6. **Uncommitted Android files.** `android/app/src/main/res/drawable-land-*` and `drawable-port-*` are
   untracked (splash screens). Commit them, or gitignore them if they are generated by `cap sync`.
   Either way, a fresh clone must build.

7. Fix the 3 `react(set-state-in-effect)` lint warnings in `src/pages/BodyMapPage.tsx:111,115,129`
   (derive during render or use initial state).
